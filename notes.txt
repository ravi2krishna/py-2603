        -> Indexing

            -> String indexing in Python allows access to "individual characters within a string" 
            using their "position", known as the "index".

            -> Python uses zero-based indexing, meaning the first character is at index 0, 
            the second at index 1, and so on.

                -> print(string[index])

            -> Positive Indexing:
            Starts from the beginning of the string.
            The index of the first character is 0.
        
            -> Negative Indexing:
            Starts from the end of the string.
            The index of the last character is -1.

            0 1 2 3 4    5
            p y t h o    n 
           -6 -5 -4 -3 -2 -1

        -> NOTE: Accessing index out of range will cause Error 

   
   -> Slicing

        -> String slicing in Python is a method for extracting a portion (substring) 
        from a larger string. It utilizes the slice operator [] with specific 
        indices to define the desired segment.

        -> syntax 

            string[start:end:step]

                -> start (optional): The index where the slice begins (inclusive). 
                    If omitted, it defaults to 0 (the beginning of the string).
                -> end (optional): The index where the slice ends (exclusive). 
                    The character at this index is not included. 
                    If omitted, it defaults to the length of the string (the end of the string).
                -> step (optional): The increment between each index during slicing. 
                    If omitted, it defaults to 1. 
                    A negative step value can be used to slice in reverse.
            
            -> Earlier we used range()

                range(start,end,step)

    -> Positional Arguments

        -> In Python, positional arguments are values passed to a function during 
        its call, where the assignment of these values to the function's parameters 
        is determined solely by their "order" (position) in the argument list. 
        
        -> The first argument in the function call is assigned to the first parameter 
        in the function definition, the second to the second, and so on. 

        -> Order Matters: If the order is incorrect, the function will receive the wrong values 
        for its intended parameters, potentially leading to errors or unexpected behavior.

    -> Keywords Arguments

        -> In Python, keyword arguments are a way to pass values to a function by explicitly 
        "naming the parameters" they correspond to, rather than relying on their position 
        in the argument list. 
        
        -> This offers several advantages, primarily in terms of code readability and flexibility.

    -> Default Arguments 

        -> In Python, default arguments allow you to define a function parameter 
            with a "pre-assigned" value. 
        
        -> If a caller does not provide an argument for that parameter during a function call, 
            the default value is automatically used. 
            If an argument is provided, it overrides the default.

        -> Placement Requirement: Default arguments must always be placed after 
            any non-default (positional) arguments in the function definition. 
            Attempting to place a non-default argument after a 
                default argument will result in a SyntaxError.

    
    -> Arbitrary Positional Arguments

        -> In Python, arbitrary positional arguments allow a function to accept 
            a variable/unknown number of non-keyword arguments. 
            This is achieved by placing an asterisk (*) before a parameter name 
                in the function definition. 
            
        -> This parameter will then collect all the extra positional arguments passed 
            to the function into a single tuple. 

    
    -> Arbitrary Keywords Arguments

        -> In Python, arbitrary keyword arguments allow a function to accept 
            a variable/unknown number of keyword arguments. 
            This is achieved by placing an asterisk (**) before a parameter name 
                in the function definition. 

        -> This parameter will be collected into a dictionary, where the names will be keys and 
            values will be dictionary values

        -> Other Languages like Java or C++ "enforces" Strict Rules for Encapsulation,  
        coming to python there is no Strict enforcing. 

            -> Java/C++ = “You’re not allowed” 

            -> Python = “You shouldn’t, but you can if you insist”

        -> While Python does not have strict access modifiers like "private" or "protected" 
        keywords found in some other languages, 
        python uses "naming conventions" to indicate the visibility of members.


        -> Hiding Data 

            -> We have public access 

                -> Without any special naming conventions or prefixes 
                are considered as public and can be accessed from anywhere 


            -> We have private access 

                -> prefixed with a double underscore (__)

                -> cannot be accessed from outside 

                -> NOTE: Python = “You shouldn’t, but you can if you insist”

                -> print(obj._MyClass__private_variable) # Accessing through mangled name is possible

            -> We have protected access 

                -> prefixed with a single underscore (_)

                -> Cannot be accessed from outside, but used within sub classes 

        -> NOTE: The prefix / naming conventions, are signals to other Developers
        that the attributes are intended for internal use only 



    -> Abstraction

        -> Abstraction in OOP is a principle that involves "hiding" complex "implementation" 
        details and showing only the essential features of an object to the user.

        -> Hiding implementation: means hiding the internal workings of an object 
        and present a simplified view. For example, when using an ATM, you only 
        interact with a simple interface (card, PIN, cash dispenser) without needing 
        to know the complex process of backend banking operations that occur. 


    -> How To achieve Abstraction In Python 

        -> Using Abstract Class 

        -> An Abstract Class In Python Functions as a "blueprint" for Other Classes,
        defining a common structure that subclasses must adhere to.

        -> Abstract Class cannot be instantiated directly, meaning you 
        cannot create objects to Abstract Class 

        -> NOTE: Abstract Classes help you enforce Contract Like Behaviors

        -> Abstract classes are Implemented in Python Using 
        "abc" module (Abstract Base Class)

            -> from abc import ABC, abstractmethod 


        -> NOTE: To Achieve abstraction, Create a class that inherits from ABC, 
        inside this class define one or more abstract methods using @abstractmethod decorator  

            -> NOTE: abstract methods have declarations, but no implementation 
            they typically contain pass 

        -> Implement Subclasses: Create Concrete Subclasses (Regular Classes)
        that inherit from abstract class, these Subclasses must Implement 
        all abstract methods which are defined in abstract class.
        If a subclass fails to Implement any abstract method, it will also
        become abstract class and cannot be instantiated

            -> NOTE: Abstract Classes help you enforce Contract Like Behaviors

    -> Polymorphism

        -> Polymorphism in OOP is the ability to take on "many forms"

        -> Polymorphism is achieved through techniques like 
        "method overloading" and "method overriding"

    
    -> Method Overloading in OOP is the ability to "define multiple methods 
    with the same name", but different parameter lists 
    (number, type, or order of arguments) within a single class

        -> NOTE: Python doesn't support Method Overloading

    -> Method Overriding

        -> When a subclass provides a new implementation of a method 
        that already exists in parent class
